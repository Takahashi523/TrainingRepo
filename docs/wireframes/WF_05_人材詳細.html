📋 ワイヤーフレーム注記　WF_05_人材詳細（v2.1）
✅ v2.1 変更点（issue #61 AI要約の状態管理 適用）
  • AI職務要約ブロックに「再生成」ボタンを追加（右下・ヒント文と同じ行）。appeal_note の変更有無に依存せず、いつでも明示的に再生成できる
  • アピールポイントが未入力の人材は再生成ボタンを非活性にし、ホバー時にツールチップで理由を表示する（disabled 要素は Chromium 系でホバーイベントを受け取らないため、実装は外側要素に title を持たせて対応）
  • 生成失敗（ai_summary_status = failed）の恒久バナーを追加：「AI要約の生成に失敗しました。「再生成」からもう一度お試しください。」。一過性のトーストだけでなく、後から詳細画面を開いても失敗状態が分かるようにする
  • 陳腐化（is_ai_summary_stale）バナーを追加：「アピールポイントの変更後、要約が更新されていません。内容が古い可能性があります。」。appeal_note 変更後に再生成が失敗し、古い要約が残ってしまうケースの救済表示。failed 中は失敗バナーを優先し二重表示しない
  • 空出力（ai_summary_status = empty）は失敗ではなく「AIが要約可能な内容を検出できませんでした」と案内（要約対象なしという正常応答のため）
  • 未生成（ai_summary_status = none）は従来通り「AI要約は未生成です」のグレー表示
  • 状態バリエーション（失敗／陳腐化／空／未生成）の表示例を詳細本体の下部に追加（実画面では ai_summary_status に応じていずれか1つのみ表示される）
✅ v2.0 変更点（仕様変更適用）
  • 職務経歴ファイルダウンロードリンク削除（アップロード機能廃止）
  • AI職務要約ヒント文更新：「職務経歴書」→「アピールポイント」（【2026-08-07 訂正】 旧記述「プロフィール情報（スキル・工程経験・アピールポイント等）」は誤り。スコアリングロジック設計書/AIプロンプト設計書 §4.3・第2章のとおり、要約の入力源は appeal_note（アピールポイント）のみで、スキル・工程経験・案件側パラメータは要約に使用しない。上部の実表示ヒント文も「AIがアピールポイントをもとに…」で本項に一致）
  • スキルタグはフリーテキスト入力のラベルで表示

⚠️ レイアウト設計メモ

  • 未生成時は「AI要約は未生成です」グレー表示を想定
  • 削除ボタンはヘッダー右端に赤文字ghostで誤操作リスクを低減
  • 【稼働可能時期の表示ロジック】稼働可能時期フィールドの値をもとにシステムが自動判定して表示する
    　未入力 → ⏱ 未定
    　日付あり → ⏱ YYYY/MM/DD〜（入力された日付をそのまま表示）
  • 【issue #61】失敗バナーと陳腐化バナーは同時表示しない（failed の間は失敗バナーのみ）。再生成中は画面全体にAIローディングオーバーレイを表示し、キャンセル不可（保存を伴う処理のため）
