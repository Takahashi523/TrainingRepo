## 設計上の前提

### 実装方針

| 項目 | 仕様 | 根拠 |
|---|---|---|
| 実装方式 | Laravel Breeze のデフォルトログイン機能を流用する | WF_01備考確定 |
| ログインID | 社内メールアドレスのみ。社外メール不可 | QA #19確定 |
| ドメインチェック | マスタ管理側（登録時）とログイン側の両方でドメイン制限を行う（二重チェック・暫定） | QA #19確定 |
| パスワードリセット | マスタ管理画面から管理者が手動対応。ユーザー向けの「パスワードを忘れた」リンクは設けない | QA #20確定 |
| ロゴ画像 | 表示しない。システム名テキスト「Nexus」のみ表示 | QA #76 / #77確定（4/29） |
| Remember me | 「ログイン情報を保存する」チェックボックスあり（WF_01確定） | WF_01確定 |

### エンドポイントの自動生成について

ログイン・ログアウトのエンドポイントは Laravel Breeze が自動生成するため、本設計書では独自実装は行わない。ルーティング定義（`routes/web.php`）への追記も不要。

| エンドポイント | 自動生成 | 備考 |
|---|:---:|---|
| `GET /login` | ✅ Breeze | ログイン画面の表示 |
| `POST /login` | ✅ Breeze | 認証処理 |
| `POST /logout` | ✅ Breeze | ログアウト処理 |
| `GET /forgot-password` | ❌ 無効化 | パスワードリセット機能は使用しない（QA #20確定） |
| `POST /forgot-password` | ❌ 無効化 | 同上 |
| `GET /reset-password` | ❌ 無効化 | 同上 |
| `POST /reset-password` | ❌ 無効化 | 同上 |
| `GET /register` | ❌ 無効化 | ユーザー登録は管理者がマスタ管理画面から行う |

> Breeze が生成するルートのうち不要なものは `routes/web.php` でコメントアウトまたは削除すること。

## 1. APIエンドポイント一覧

> 前提・凡例・SharedProps・共通HTTPレスポンスは `00_共通仕様_APIエンドポイント一覧.md` の前提セクションに準じる。

### エンドポイント一覧表

| # | メソッド | URL | Controller#Action | アクセス可能ロール | 対応WF |
|---|---|---|---|---|---|
| 1 | GET | /login | （Breeze自動生成） | 未認証ユーザーのみ | WF_01 |
| 2 | POST | /login | （Breeze自動生成） | 未認証ユーザーのみ | WF_01 |
| 3 | POST | /logout | （Breeze自動生成） | 認証済みユーザー | 全画面共通 |

> 認証済みユーザーが `GET /login` にアクセスした場合、Laravel Breeze のデフォルト挙動により `/dashboard` へリダイレクトされる。

---

### GET /login　Props（#1）

```jsonc
{
  // Laravel Breeze デフォルトのログイン画面を使用する
  // Inertia.js の場合は Pages/Auth/Login.tsx がレンダリングされる
  // 独自 Props の追加なし
}
```

---

### POST /login　送信データ（#2）

| フィールド名 | 型 | 必須 | 備考 |
|------------|---|:----:|------|
| email | string | ✓ | メールアドレス（ログインID）。社内メールアドレスのみ（QA #19確定） |
| password | string | ✓ | パスワード |
| remember | bool | 任意 | 「ログイン情報を保存する」チェック状態。true でセッション延長（WF_01確定） |

#### レスポンス

| 条件 | 動作 |
|---|---|
| 認証成功 | `/dashboard` へリダイレクト |
| 認証失敗（メール・パスワード不一致） | 422。エラーメッセージ：「メールアドレスまたはパスワードが正しくありません」 |
| レート制限超過（連続失敗） | 429。Breeze デフォルトのスロットリングが適用される |

---

### POST /logout　送信データ（#3）

送信データなし（CSRFトークンのみ）。

#### レスポンス

| 条件 | 動作 |
|---|---|
| 成功時 | セッションを破棄し `/login` へリダイレクト |

## 2. 他機能との関連

| 関連機能 | 内容 |
|---|---|
| マスタ管理（ユーザー管理） | ユーザーの登録・パスワードリセットはマスタ管理画面から管理者が行う（QA #20確定）。ログイン画面に「アカウントを作成」「パスワードを忘れた」リンクは設けない |
| 全画面共通（未ログイン時） | 未認証ユーザーが認証が必要なURLへアクセスした場合、`auth` ミドルウェアにより `/login` へリダイレクトされる。**Inertiaリクエストの場合は302ではなく409 + `X-Inertia-Location` ヘッダーでフルページ遷移を指示する**（非Inertia・JSONを期待するリクエストは401、それ以外の非Inertiaは従来どおり302）。302のままだとDELETE/PUT/PATCH等の非GETリクエストがメソッドを保持したまま `/login` を再度叩いてしまい、405エラーになるため（issue #63、`UnauthenticatedInertiaRedirector`。ログイン後に元の画面へ戻せるよう`url.intended`のセッション保存もあわせて行う。詳細は `00_共通仕様_APIエンドポイント一覧.md` の共通HTTPレスポンスを参照） |
| 全画面共通（CSRFトークン切れ） | CSRFトークン不一致（419）が発生した場合の復帰導線は issue #70（PR #77・共通エラーページ）の`ErrorPageResponder`が担当する。ログイン済みなら元画面へ`back()` + フラッシュ、未ログインならログイン画面へ`status`を渡して表示する。当初issue #63の②として本ドキュメントの対象に含めていたが、対応範囲の重複によりPR #77に一本化した |
| SharedProps | ログイン後は `auth.user`（id / name / role）が全画面の SharedProps に含まれる。詳細は `00_共通仕様_APIエンドポイント一覧.md` の前提セクションを参照 |
