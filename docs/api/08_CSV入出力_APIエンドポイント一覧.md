### インポート方式

| 条件 | 処理 |
|---|---|
| CSVの `id` 列が空 | 新規追加として処理 |
| CSVの `id` 列に既存ID | 既存データを上書き更新 |
| CSVの `id` 列に存在しないID | エラーとして処理（全行ロールバック） |

> エクスポートしたCSVを編集して再インポートする運用を想定（WF_11確定）。
> **エラー行処理方針**：1行でもエラーがある場合は全行ロールバックし、エラー内容を返す。データ整合性を優先するため「スキップして成功件数を返す」方式は採用しない。
> **並行制御（ロストアップデート）について（O-1 / 2026-07-30）**：`id` 指定の更新は**全項目上書き**のため、エクスポート後に別ユーザーが同一レコードを編集していると、その変更を無警告で上書きしうる（画面編集の #45 と同一問題クラス・別入口）。**本実装では暫定的に許容**し、恒久対応は #45 で追加する `version` 列による楽観ロックに **CSVインポートも相乗り**して後付けする（更新行の `version` 照合→不一致行はエラー、および CSV 更新時の `version` インクリメント）。#45 は本実装より後のため、本実装時点では version 照合は行わない。運用上は「CSV作業中は対象レコードを画面編集しない」ことを推奨し、WF_11 のヒントにも注意を記載する。

#### 空行の扱い（2026-07-30 確定）

- **空行＝改行だけの行（文字が1つも無い行）**。位置（末尾・中間）を問わず**スキップ**し、`total_rows` / `created` / `updated` / エラーのいずれにも**計上しない**（`total_rows = created + updated` が常に一致するようにする）。
- それ以外はすべて「データ有り」の行として処理する。`,,,,`（列数は合うが全セル空）は必須項目の項目エラー、**スペースだけの行は1列としてパースされ後述のレイアウトエラー**になる（いずれも空行ではなくデータ行）。
- エラー報告の `row`（行番号）は**元のCSV行番号（論理レコード番号）を維持**する（空行をスキップしても繰り上げない）。Excel の行番号と一致させ修正箇所を特定しやすくするため。
- 補足：この「改行だけの行はスキップ」は一般的なCSVライブラリの既定挙動（PHP `fgetcsv` / League\Csv 等）と一致する。

#### バリデーションの順序（2026-07-30 確定）

値がずれた状態で項目検証すると誤ったエラーになるため、**レイアウトチェックを項目バリデーションより先**に行う。

1. **ファイルレベル**：拡張子・サイズ・文字コード（UTF-8）。NG なら即 422。
2. **ヘッダー行**：想定カラム構成と一致するか。**ヘッダーが不正なら全体を中断**（マッピング不能なため行処理に進まない・単一の全体エラーを返す）。
3. **行レイアウト（列数）**：各データ行の列数がヘッダーと一致するか。不一致は `field: null` の構造エラー（例「列数がヘッダーと一致しません（この行1列 / ヘッダー26列）。列数をヘッダーと揃えてください。」）。スペースだけの行はここで捕捉される。**エラー文言は原因だけでなく対処（何をすべきか）まで含める方針**。
4. **項目バリデーション**：各セルのルール（§8）。

> **収集方針**：列数が不正な行は構造エラーを記録し、**その行の項目バリデーションはスキップ**する（値がずれているため）。列数が正しい行は項目バリデーションを実施。構造エラーと項目エラーを**1回のレスポンスにまとめて**返す（行は独立のため正常行の検証は続行＝往復を増やさない）。1件でもあれば全行ロールバック。ヘッダー不正のみ例外で即中断。

#### ヘッダー照合・id重複・0行・日付・冪等性（O-7〜O-11 確定）

- **ヘッダー照合（O-7）**：**列は名前（ヘッダー文字列）で対応づける**（列順の入替は許容）。ヘッダー段階で次の4種を検出し、いずれかがあれば**1エントリ（行1・`field:null`）にまとめてヘッダーエラーで全体中断**する：①**必須列の欠落**（マッピング不能）／②**空ヘッダー**（末尾カンマ等。列位置を明示）／③**重複ヘッダー**（同名列は対応が曖昧）／④**未知の列**（定義にない列名）。ただし `AI要約`/`主担当名`/`サブ担当名` などの **export-only 列は「既知の列」として許容**（取り込み時は値を無視）し、エクスポートした CSV をそのまま再インポートできるようにする。

> **【2026-08-02 修正】未知列を「無視」から「エラー」に変更**
> **背景：** 未知列を無視する仕様だと、末尾の余分なカンマ由来の空ヘッダーや、誤って足した列が `headerCount` に加算され、**全データ行が「列数がヘッダーと一致しません」で弾かれて**原因（ヘッダー側の余分な列）が分かりにくくなっていた。
> **理由：** ヘッダー段階で未知列・空ヘッダーを1件の明確なエラー（「不明な列があります：…」）として中断すれば、原因がヘッダーだと即分かり、無駄な全行エラーも防げる。export-only 列は `exportHeaders()`（＝既知の列）に含むため誤検知しない（再インポートの往復は維持）。判定は `exportHeaders()` をホワイトリストにした `array_diff`。
- **ファイル内 id 重複（O-8）**：同一 `id` が複数行に現れた場合、当該行を構造系エラー（`field:null`「同一IDが複数行にあります」）とする（二重更新の不定動作を防ぐ）。新規行（`id` 空）は engineers/projects に自然キー UNIQUE が無いため、内容が重複していても**各行が別レコードとして新規作成される**（重複登録され得る点は仕様）。
- **データ0行（O-9）**：ヘッダーのみで**データ行が0件**（空行スキップ後）の場合は成功にせず、**422「インポートする対象データがありません」**を返す。
- **日付形式（O-10）**：日付列（`birth_date`/`available_from`/`start_date`）は **`date_format:Y-m-d`（`YYYY-MM-DD`）のみ受理**（フォームの緩い `date` より厳格。O-10 が優先）。`2026/1/1` 等は日付エラー。Excel で開くと日付列が自動変換されうるため、WF_11 のヒントで注意喚起する。大きな id の指数表記・先頭ゼロ落ちも同様にユーザー側の注意事項としてヒントに記載。
- **冪等性（O-11）**：サーバ側の冪等キーは実装しない（内部ツール。クライアントの `processing` による二重送信防止＋実行後のファイルクリアで実務上十分）。二重POSTがあれば新規行は二重登録され得る点は**許容**とする。

### ファイル仕様（確定）

| 項目 | 仕様 |
|---|---|
| 準拠仕様 | **RFC 4180**（CSVの事実上の標準） |
| 採用ライブラリ | **`league/csv` `^9`**（RFC4180・BOM入出力・ストリーム対応。入出力の引用符/エスケープ/BOMを自前実装せず担保する。2026-07-31 導入） |
| 対応形式 | `.csv`（UTF-8 / BOM付き） |
| 最大ファイルサイズ | 5MB |
| 改行コード | CRLF・LF両対応 |
| 文字コード | UTF-8（BOMあり・なし両対応） |
| 区切り文字 | カンマ `,` |
| 引用符 | ダブルクオート `"`。**値がカンマ `,`・ダブルクオート `"`・改行を含む場合のみ囲みが必須**（それ以外は囲み不要）。値中の `"` は `""` にエスケープ。**シングルクオート `'` は引用符として扱わない（通常文字）** |

> **RFC 4180・引用符の実装注意（2026-07-30 確定）**
> - **エクスポート**：RFC4180準拠のCSVライター（PHP `fputcsv` / League\Csv 等）を用い、カンマ・改行・`"` を含むフィールド（`appeal_note` / `remarks` / `description` / `work_env` / `rate_note` などの自由記述）を自動でダブルクオート囲み＋`""`エスケープする。`implode(',')` のような手組みは禁止。
> - **インポート**：RFC4180準拠のパーサ（`fgetcsv` / League\Csv 等）を用いる。`"..."` 内の改行は**1論理レコードの一部**として扱うため、`\n` での単純分割は禁止。
> - **BOM ストリップ（O-6 確定）**：BOM 付きでエクスポートした CSV を再インポートすると、先頭ヘッダーが `﻿id` になりヘッダー照合が落ちる。**インポート時はファイル先頭の UTF-8 BOM（`\xEF\xBB\xBF`）をパース前に除去**する（League\Csv は `Reader::setEnclosure` 等と別に BOM スキップを持つ。`fgetcsv` 手実装時は自前で先頭3バイトを判定・除去）。文字コード判定（UTF-8 チェック）は BOM 有無どちらも UTF-8 として通す。
> - 上記に伴い、空行判定・行番号・列数チェックはすべて**論理レコード単位**で行う（引用符内の改行は行を割らない。行番号は Excel が示す論理行と一致）。

> **CSVインジェクション対策（O-4 確定 / 2026-07-30）**
> エクスポートしたCSVは Excel・Google スプレッドシート・LibreOffice・Numbers など**任意の表計算アプリ**で開かれうる。セル値が数式トリガー文字で始まると数式実行やデータ外部送信（`=IMPORTXML` 等）につながるため、以下で緩和する（Excel 固有の対策ではない・クロスプラットフォームで有効）。
> - **危険文字**：`=` `+` `-` `@`、および先頭のタブ（`0x09`）・CR（`0x0D`）。
> - **エクスポート**：値が危険文字で始まるセルは**先頭に `'` を付与**する（全列対象。特に自由記述 `appeal_note`/`remarks`/`description`/`work_env`/`rate_note`/各 `name`）。`'` は表計算アプリ共通で「文字列として扱う」記法。
> - **インポート（条件付き復元）**：セル値が **`'` で始まり、かつ直後の文字が危険文字**の場合のみ、先頭の `'` を1つ除去して元値に復元する。それ以外の先頭 `'`（例 `'メモ`）は**ユーザーが意図した文字として保持**する。これにより「機械が付けた `'`」と「人が入れた `'`」を区別し往復整合を保つ。
> - **残余エッジ**：ユーザーが意図的に `'=x`（アポストロフィ＋危険文字）という値を入力していた場合のみ、取込時に `=x` に変化する。頻度極小・実害軽微のため許容とする。

> **ファイル名の取り扱い（O-12 確定 / 2026-07-31）**
> - **エクスポート（ダウンロード名）**：`Content-Disposition` の filename は**完全にサーバー側で生成**する（`{resource}_{Ymd_His}.csv`、例 `engineers_20260522_143022.csv`）。ユーザー入力は一切含めず、文字集合を `[A-Za-z0-9_]` ＋ `.csv` に限定する。これによりヘッダー/CRLF インジェクションの余地を無くす。
> - **インポート（アップロード元ファイル名）**：`getClientOriginalName()` は攻撃者制御の入力とみなす。**保存パス・ファイルシステム操作に元ファイル名を一切使わない**（CSVは保存せず、一時ファイルをフレームワーク生成名で処理＝パストラバーサル無効化）。拡張子判定は**ファイル名を信用せず** `mimes:csv,txt` ＋実拡張子チェックで行う（§8）。ログ出力時は改行等をサニタイズ（ログインジェクション防止）。
> - **取込前のファイル名表示（`CsvUploader`）**：画面に出すのはクライアントの `File.name`（ユーザー制御）。React の自動エスケープで描画し `dangerouslySetInnerHTML` は使わない。加えて**視覚スプーフィング対策**として、表示用に制御文字・双方向制御文字（bidi override, `U+202E` 等）を除去し、長すぎる名前は省略表示する。表示以外（パス・保存名等）には使わない。

> **`users` の中身（担当者ID凡例への流用）**：`users` は **`users` テーブルの実データ（全件）を `SELECT id, name` で取得したライブ一覧**（サンプルではない）。エクスポート絞り込みの担当営業プルダウンと、**画面上の「担当者ID一覧」ポップオーバー表示に共用**する。営業が新規行に入力すべき担当者ID（`主担当ID` / `サブ担当ID`）をこのポップオーバーで確認できるようにするため、追加のエンドポイントは設けない。

### POST /csv/engineers/import　送信データ（#2）

> ファイルアップロードのため `Content-Type: multipart/form-data` で送信する。

| フィールド名 | 型 | 必須 | 備考 |
|------------|---|:----:|------|
| file | file | ✓ | CSVファイル。`.csv` 形式・最大5MB・UTF-8（BOM付き対応） |

#### レスポンス

| 条件 | HTTPステータス | レスポンス内容 |
|---|---|---|
| 全行正常処理 | 200 OK | 処理結果サマリーを返す（後述） |
| ファイルバリデーションエラー | 422 | エラー内容を返す |
| 1行でもエラーあり | 422 | 全行ロールバック。エラー行情報を返す（後述） |

```jsonc
// 成功時レスポンス（200 OK）
{
  "summary": {
    "total_rows": "int",  // 処理対象行数（ヘッダー行除く）
    "created": "int",     // 新規追加件数
    "updated": "int"      // 更新件数
  }
}

// エラー時レスポンス（422）
{
  "errors": [
    {
      "row": "int",           // エラー発生行番号（1オリジン・ヘッダー行を1行目としてカウント）
      "field": "string|null", // エラー項目名（行構造の崩れ等・項目を特定できない場合は null）
      "messages": ["string"]  // その項目の失敗メッセージ（日本語）を配列で返す。1項目に複数の不備があれば複数要素
    }
  ]
}
```

> **エラーの粒度**：1項目（=1セル）につき、失敗したバリデーションを**すべて**返す（`bail` は使わない）。例：氏名カナが「漢字」かつ「100文字超」なら `messages` に「カナで入力してください」「100文字以内で入力してください」の2件を格納する。同一 (row, field) は**1エントリにまとめ**、`messages` 配列に列挙する（区切り文字での連結はしない）。行構造の崩れ（列数不一致など）は項目に紐づかないため `field: null` の1エントリとして返す。
> **画面表示**：モーダルのエラー表は (行, 項目) を1行にまとめ、「エラー内容」セル内で `messages` を**改行の箇条書き（`・`）**で縦に並べる（読点でのベタ連結はしない）。「行」「項目」はセルごとに1回だけ表示する。

> **実装注意（トランザクション）**：1行でもエラーがある場合は全行ロールバックする。エラー内容をすべて収集してから422を返すこと（最初のエラーで中断しない）。
> **実装注意（フィードバックUI）**：インポート結果は**モーダル（Dialog）で表示**し、インポートフォーム自体は伸ばさない。成功時は「新規追加：〇件 / 更新：〇件」、失敗時はモーダルに「件数サマリ＋エラー内容の一覧（行番号・項目・メッセージ、スクロール可能）」を表示する。**モーダルを閉じても結果は破棄せず、1行の結果バナーを残して「詳細を表示」で再オープンできること**（新ファイル選択・再インポートでクリア）。詳細な表示例は `wireframes/WF_11_CSV入出力.html`（v1.2）を参照。
>
> > **【2026-07-30 修正】フィードバックUIをインライン表示 → モーダル表示に変更**
> > **背景：** エラー行一覧をフォーム直下にインライン表示すると、結果が出るたびにインポート欄が下へ伸びてレイアウトが押し下げられる問題があった。
> > **理由：** 結果は「読んで確認し、CSVを直して再アップロードする」読み取り専用フィードバックであり、全行ロールバック（部分成功なし）で行単位の操作も不要。モーダルで分離すれば背景を押し下げず動線も自然。ただしモーダルは閉じると内容を失うため、結果を保持し結果バナーから再表示可能にする。
>
> **実装注意（モーダルの閉じ方）**：結果モーダルは**オーバーレイ外クリックでは閉じない**（閉じるのは「閉じる」ボタン／✕／Esc のみ）。エラー行をコピーする際のドラッグ抜けや選択解除クリックで誤って閉じるのを防ぐため。`ui/dialog` なら `onInteractOutside` を `preventDefault`、または Radix AlertDialog 系（`ConfirmDialog` の土台）の既定挙動を用いる。
> **実装注意（結果のクリア／保持）**：モーダルの「閉じる／✕／Esc」は**非表示のみ**で結果は破棄しない（1行の結果バナーを残し「詳細を表示」で再オープン可）。結果データを**破棄（クリア）するのは「新しいファイルを選択」「ファイル選択の取り消し」の時**。タブ（人材⇄案件）ごとに結果は独立保持し、切替で相手を消さない。成功時は成功トーストで通知しつつ、**成功サマリ（新規追加◯件 / 更新◯件）の1行バナーを常設**する（クリアはエラーバナーと同じく「新ファイル選択・ファイル取消」の時）。
>
> > **【2026-08-02 修正】成功時も1行バナーを常設する（従来：成功はトーストのみで自動消去）**
> > **背景：** 当初は「成功は修正作業が不要」としてトーストのみ・自動消去としていたが、CSV インポートは最大5,000行の一括書き込みで高影響。4秒で消えるトーストは見逃しやすく、想定外の件数（例：新規のつもりが大量更新）に気づけず、実行後はファイル選択もクリアされるため「結局どうなったか」を後から確認できなかった。
> > **理由：** 結果の重要度に見合うフィードバックにするため、成功でも件数を欄に残す。エラーバナーと対の成功バナー（`ImportSuccessBanner`）とし、ライフサイクル（新ファイル選択・取消でクリア）・配色（成功トーストと同じ緑系）を既存と統一。WF_11 v1.2 も「成功時はトースト**または**1行バナー」を許容しており（`wireframes/WF_11_CSV入出力.html`）、その選択肢のうち「トースト＋常設バナー」を採用した。
>
> **実装注意（再インポートの動線）**：実行ボタンは「インポート実行」1つのみで、**「再インポート」専用ボタンは設けない**。エラーを修正した後の再取込は「修正したファイルを選び直す → インポート実行」という同一フロー（新ファイルを選択した時点で前回のエラー結果はクリアされる）。
>
> **実装注意（アップロードファイルの扱い）**：受け取ったCSVは一時ファイルとして処理するのみで**サーバーに保存しない**。画面側は**実行後、成功・失敗ともファイル選択をクリア**する（失敗時も結果バナー／再表示モーダルは保持）。ブラウザの `File` は選択時点のスナップショットであり、エラー後に同一ファイルを修正しても選択済み内容は古いままとなるため、クリアして「修正→選び直し→再実行」に統一し、古い内容の誤再インポートを防ぐ。ファイル未選択時は「インポート実行」ボタンを非活性にする。
> **実装注意（大量データ・同期処理 / O-13 確定 2026-07-31）**：本実装は**同期処理**（クリック→完了まで画面ブロック）。実行中は `processing` 無効化に加え**ローディングオーバーレイ**（`Common/AiLoadingOverlay` と同じ明色ブラー幕）を表示する。
> - **想定規模**：小規模社内ツールのため設計目標 〜1,000 行、安全上限 〜5,000 行（preload＋バッチ書き込みで数秒〜十数秒、PHP 既定 `max_execution_time` 30s に対し余裕あり）。
> - **行数上限ガード**：**データ行が 5,000 行を超える場合はエラー**（「一度にインポートできるのは5,000行までです。ファイルを分割してインポートし直してください」）とし、同期リクエストのタイムアウトを確実に回避する。5MB のファイルサイズ上限と併用。
> - **N+1 回避（必須）**：`exists:users,id`（`main_user_id`/`sub_user_id`）や更新行の既存 id 判定を**行ごとに DB 問い合わせしない**。`SELECT id FROM users` と更新対象の既存 id 群を**最初に1回ロードしてメモリ照合**する。
> - **書き込み**：全行1トランザクション内で**バッチ（chunk）**で INSERT/UPDATE し、単発クエリの多発を避ける（`created`/`updated` 件数集計・将来の `version` 更新と両立する範囲で）。
> - 上限を超える運用が常態化した場合は Laravel Queue による非同期処理（進捗表示・完了通知・結果保持UI）への移行を検討する。
