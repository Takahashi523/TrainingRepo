# 人材削除API設計書

## API基本情報

### API名
- 人材削除API

### エンドポイント
`
DELETE /api/engineers/{id}
`

### 概要
- 指定した人材情報を削除する。
- ユーザー権限に応じて削除方法が異なる
  - 管理者：物理削除
  - 一般ユーザー：ステータスを「削除（無効）」に変更（論理削除）

## リクエスト仕様

### パスパラメータ
| パラメータ名 | 型 | 必須 | 説明 |
|---|---|---|---|
| id | integer | 必須 | 人材ID |

## 削除仕様

### 権限別挙動
| ユーザー種別 | 挙動 |
|---|---|
| 管理者    | 対象データを物理削除する |
| 一般ユーザー | status_id を「削除（無効）」に更新する |

### ステータス仕様（論理削除）
- ステータスマスタに「削除（無効）」を定義する
- 一般ユーザーによる削除時はこのステータスに更新する

### 一覧・検索への影響
- 「削除（無効）」のデータは一覧・検索結果に表示しない

## 関連データの取り扱い

### 管理者による物理削除時
以下の関連データも削除対象とする
- engineer_skill（人材スキル）
- engineer_user（担当営業）
- 職務経歴書ファイル（ストレージ）

## ファイル削除仕様
| 条件 | 挙動 |
|---|--- |
| 管理者による削除 | ストレージ上のファイルも削除 |
| 一般ユーザーによる削除 | ファイルは保持（論理削除のため） |

## レスポンス仕様

### ステータスコード
| ステータス | 説明 |
|---|---|
| 200 | 削除成功（論理削除） |
| 403 | 権限なし |
| 404 | 対象データなし |
| 500 | サーバーエラー |

## レスポンス例

### 削除
```
JSON
{
  "message": "人材情報を削除しました",
  "delete_type": "logical" // または "physical"
}
```

## エラーレスポンス

### 対象データなし
```
JSON
{
  "message": "対象の人材が存在しません"
}
```

### 権限エラー
```
JSON
{
  "message": "この操作を行う権限がありません"
}
```

## 処理概要
1. 対象データ存在チェック（存在しなければ404）
2. ユーザー権限チェック
3. トランザクション開始

- 管理者の場合（物理削除）
4. 関連データ削除
   - engineer_skill
   - engineer_user
5. 職務経歴書ファイル削除（存在する場合）
6. engineersテーブル削除（物理削除）

- 一般ユーザーの場合（論理削除）
4. status_id を「削除（無効）」に更新
5. コミット
6. レスポンス返却
- ※エラー発生時はロールバック

## 使用テーブル
| テーブル名 | 日本語名 | 説明 |
|---|---|---|
| engineers | 人材 | 人材の基本情報 |
| engineer_skill | 人材スキル | スキル中間テーブル |
| engineer_user | 人材担当営業 | 営業担当 |
| statuses | ステータスマスタ | ステータス管理 |
