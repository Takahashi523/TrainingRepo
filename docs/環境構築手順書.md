# メンバー向け 環境構築手順書

> 対象者：開発メンバー全員  
> 前提：前提：リポジトリの初期セットアップが完了済みであること

---

## 前提条件

以下の2つのみホスト OS にインストールしてください。  
それ以外（Node.js・PHP・Python 等）は**一切インストール不要**です。

| ツール | 用途 | インストール先 |
|---|---|---|
| Docker Desktop | コンテナ実行基盤 | https://www.docker.com/products/docker-desktop/ |
| VS Code | エディタ | https://code.visualstudio.com/ |

### VS Code 拡張機能のインストール

- **Dev Containers**（`ms-vscode-remote.remote-containers`）

---

## 1. リポジトリのクローン

```bash
git clone git@github.com:<organization>/TrainingRepo.git
```

---

## 2. VS Code でフォルダを開く

> **注意：** ファイルを直接開くのではなく、**フォルダ単位**で開いてください。

1. VS Code のメニューから `ファイル` → `フォルダを開く`
2. クローンした `TrainingRepo/` フォルダを選択

---

## 3. Dev Container の起動

1. フォルダを開くと右下にポップアップが表示されます

```
「コンテナーで再度開く」
```

2. `コンテナーで再度開く` をクリック
3. 以下の選択ダイアログが表示されます

```
・SES Matching - Laravel  ← Laravel チームはこちらを選択
・SES Matching - Python   ← Python チームはこちらを選択
```

> **初回は10〜20分程度かかります。** 2回目以降はキャッシュが効くため1〜2分で起動します。

---

## 4. チーム別 コンテナ起動方法

担当チームに応じて起動するサービスを選択してください。

### Laravel チーム

Laravel・MySQL・MinIO のみ起動します。Python コンテナは不要です。

```bash
# laravel/ ディレクトリで実行
cd laravel
docker-compose up -d
```

| 起動サービス | 用途 |
|---|---|
| laravel | Laravel + React（Inertia.js）|
| mysql | データベース |
| minio | S3 ローカル代替 |

### Python チーム

Python・MySQL・MinIO を起動します。マッチングエンジンは DB（MySQL）と S3（MinIO）にアクセスするため両方必要です。

```bash
# リポジトリルートで実行
docker-compose up -d python mysql minio
```

| 起動サービス | 用途 |
|---|---|
| python | FastAPI マッチングエンジン |
| mysql | マッチングスコア・データ参照用 DB |
| minio | 職務経歴書等のファイル参照用 S3 代替 |

### 全サービス統合起動（結合確認・統合テスト時）

```bash
# リポジトリルートで実行
docker-compose up -d
```

## 9. MinIO（S3 ローカル環境）の初期設定

> MinIO のデータは各自のローカル環境で完結します。メンバー間でのデータ共有は不要です。パスワードはローカル開発用のダミー値のため全員共通で問題ありません。

1. ブラウザで `http://localhost:9001` を開く
2. ログイン情報を入力
   - ユーザー名：`minio`
   - パスワード：`minio123`
3. `Buckets` → `Create Bucket` → バケット名 `ses-matching` で作成

## 12. ライブラリの追加手順

### Laravel チーム：PHP ライブラリの追加（Composer）

PHP ライブラリは `composer.json` で管理されています。

```bash
# コンテナ内で実行
docker exec -it trainingrepo-laravel-1 sh
composer require <パッケージ名>

# 例：CSV 出力ライブラリの追加
composer require league/csv:^9.0
```

追加後は `composer.json` と `composer.lock` が更新されます。必ず Git にコミットしてください。

```bash
git add composer.json composer.lock
git commit -m "feat: league/csv を追加"
```

### Laravel チーム：JavaScript ライブラリの追加（npm）

JavaScript ライブラリは `package.json` で管理されています。

```bash
# コンテナ内で実行
docker exec -it trainingrepo-laravel-1 sh

# 本番用ライブラリ
npm install <パッケージ名>@<バージョン> --legacy-peer-deps

# 開発用ライブラリ
npm install <パッケージ名>@<バージョン> --save-dev --legacy-peer-deps

# 例：日付ライブラリの追加
npm install dayjs@1.11.10 --legacy-peer-deps
```

> **注意：** バージョンは必ず固定してください。PyPI（https://www.npmjs.com）でバージョンを確認してから追加します。

追加後は `package.json` と `package-lock.json` が更新されます。必ず Git にコミットしてください。

```bash
git add package.json package-lock.json
git commit -m "feat: dayjs を追加"
```

### Python チーム：Python ライブラリの追加（pip）

Python ライブラリは `requirements.txt` で管理されています（Node.js の `package.json` 相当）。

**手順1：`requirements.txt` にバージョンを固定して追記**

```
# python/requirements.txt
fastapi==0.115.0
uvicorn==0.30.0
...
numpy==2.0.0    # ← 追加したいライブラリをバージョン固定で追記
```

> **バージョンの確認方法：** https://pypi.org で検索して最新の安定版を確認します。

**手順2：コンテナを再起動（自動でインストールされる）**

```bash
docker-compose restart python
```

コンテナ起動時に `pip install -r requirements.txt` が自動実行されるため、追記したライブラリが自動でインストールされます。

**手順3：Git にコミット**

```bash
git add python/requirements.txt
git commit -m "feat: numpy を追加"
```

> **注意：** バージョンを固定せず `numpy` のように書くとメンバーごとに異なるバージョンが入る可能性があります。必ず `numpy==2.0.0` のようにバージョンを固定してください。

## 13. よくあるトラブルと対処法

### Dev Container が起動しない

フォルダ単位で開いているか確認してください。

### コンテナのログ確認

```bash
docker-compose logs laravel
docker-compose logs python
```

### マイグレーションが失敗する

```bash
php artisan migrate
```

### MinIO にファイルがアップロードできない

`laravel/.env` の以下が設定されているか確認してください。

```
AWS_USE_PATH_STYLE_ENDPOINT=true
```

### Python ライブラリが反映されない

`requirements.txt` に追記後にコンテナを再起動してください。

```bash
docker-compose restart python
docker-compose logs python   # インストールログを確認
```

## 15. コンテナの停止

```bash
# 停止（データは保持）
docker-compose stop

# 停止 + コンテナ削除（データは保持）
docker-compose down

# 停止 + データも全削除（DB・MinIO のデータが消えます）
docker-compose down -v
```

> **注意：** `-v` オプションはローカルの DB・MinIO データが全て消えます。必要な場合のみ使用してください。

---

## 16. やり直す場合

```bash
# コンテナ・ボリュームを全削除
docker-compose down -v

# Git 管理外ファイルを全削除（vendor・node_modules 等）
git clean -fdx

# 手順5からやり直す
```
