## 10. テスト環境の設定（Laravel チームのみ）　🐳 Dev Container

`.env.testing` はコミット対象外のため、各自で作成が必要です。

```bash
cp .env .env.testing
```

コピー後、`.env.testing` を開いて以下の項目を書き換えてください。

```
APP_ENV=testing

DB_CONNECTION=sqlite
DB_DATABASE=:memory:

SESSION_DRIVER=array
CACHE_STORE=array
QUEUE_CONNECTION=sync
MAIL_MAILER=array
```

> **ℹ️ `ALLOWED_EMAIL_DOMAINS` について：** `cp .env .env.testing` でコピーすると `.env` の `ALLOWED_EMAIL_DOMAINS` も引き継がれますが、テスト実行時は `phpunit.xml` の `<env name="ALLOWED_EMAIL_DOMAINS" value=""/>` が先に空をセットし、後続の `.env.testing`（dotenv）は既存値を上書きしないため、テストでは常に空（＝ドメイン制限なし）に固定されます。`.env.testing` 側で設定・削除する必要はありません。
> これは、Factory が生成する `@example.*` メールが許可ドメインの `ends_with` 検証で弾かれ、各自のローカル値によってテストが不安定（flaky）になるのを防ぐためです。ドメイン制限そのものを検証するテストは、テスト内で `config(['organization.allowed_email_domains' => [...]])` を明示設定しているため影響を受けません。

設定後、テストが通ることを確認してください。

```bash
php artisan test
```

## 11. 動作確認

| サービス | URL | 確認内容 |
|---|---|---|
| Laravel | http://localhost:8000 | ログイン画面が表示される |
| Python | http://localhost:8001/docs | Swagger UI が表示される |

### ⚠️ トラブル：http://localhost:8000 にアクセスすると画面が真っ白になる場合

**原因：** Vite の HMR 接続先が `0.0.0.0` になっており、ブラウザから JS が読み込めていません。

`laravel/vite.config.ts` を以下のように修正してください。

```ts
export default defineConfig({
  server: {
    host: '0.0.0.0',
    port: 5173,
    hmr: {
      host: 'localhost',  // ← これを追加
    },
  },
})
```

修正後、`npm run dev` を再起動してください。

## 12. 初期ログイン情報（Laravel チームのみ）

### 開発・テスト環境

`php artisan db:seed` により、開発・テスト用の管理者アカウントが投入されます（`local` / `testing` 環境限定）。

| 項目 | 値 |
|---|---|
| メールアドレス | `test@example.com` |
| パスワード | `password` |

> **⚠️ この既知アカウントは `local` / `testing` 環境でのみ作成されます。** 本番（`production`）では `db:seed` を実行しても作成されません（`DatabaseSeeder` で環境ガード済み）。

### 本番環境の初期管理者（リリース時）

マスタ管理（`/master`）は管理者専用で自己登録もないため、リリース時は **Artisan コマンドで最初の管理者を作成**します。平文パスワードを `.env` やリポジトリに残さないよう、対話入力（`--password` 省略で非表示入力）で作成してください。

> **⚠️ リリース前チェック（必須）：`ALLOWED_EMAIL_DOMAINS` を必ず設定すること。**
> ユーザーのメールアドレス（＝ログインID）に許可する社内ドメインを `.env` にカンマ区切りで設定します（例：`ALLOWED_EMAIL_DOMAINS=example.co.jp,example.com`）。
> **未設定のまま本番稼働すると、ドメイン制限が完全に無効化され（形式チェックのみ）、任意ドメインのメールでユーザー登録できてしまいます。** `.env` は git 管理外のため設定漏れに気づきにくく、リリース担当者は初期管理者作成の前にこの設定を必ず確認してください。

```bash
# 対話形式（推奨・パスワードは非表示入力）
php artisan app:create-admin

# 引数指定（CI 等で自動化する場合）
php artisan app:create-admin --name="山田 太郎" --email="admin@example.com" --password="＜8文字以上・英字と数字＞"
```

- パスワードは `Password::defaults()`（8文字以上・英字と数字を含む）でバリデーションされます。
- メールアドレスは一意制約＋（`ALLOWED_EMAIL_DOMAINS` 設定時は）ドメイン制限が適用されます。
- 作成後は、この管理者でログインしてマスタ管理から他ユーザーを追加できます。

## 13. ライブラリの追加手順

### Laravel チーム：PHP ライブラリの追加（Composer）　🐳 Dev Container

PHP ライブラリは `composer.json` で管理されています。

```bash
# コンテナ内で実行
composer require <パッケージ名>

# 例：CSV 出力ライブラリの追加
composer require league/csv:^9.0
```

追加後は `composer.json` と `composer.lock` が更新されます。必ず Git にコミットしてください。

```bash
git add composer.json composer.lock
git commit -m "feat: league/csv を追加"
```

### Laravel チーム：JavaScript ライブラリの追加（npm）　🐳 Dev Container

JavaScript ライブラリは `package.json` で管理されています。

```bash
# コンテナ内で実行

# 本番用ライブラリ
npm install <パッケージ名>@<バージョン> --legacy-peer-deps

# 開発用ライブラリ
npm install <パッケージ名>@<バージョン> --save-dev --legacy-peer-deps

# 例：日付ライブラリの追加
npm install dayjs@1.11.10 --legacy-peer-deps
```

> **注意：** バージョンは必ず固定してください。https://www.npmjs.com でバージョンを確認してから追加します。

追加後は `package.json` と `package-lock.json` が更新されます。必ず Git にコミットしてください。

```bash
git add package.json package-lock.json
git commit -m "feat: dayjs を追加"
```

### Python チーム：Python ライブラリの追加（pip）　🐳 Dev Container

Python ライブラリは `requirements.txt` で管理されています（Node.js の `package.json` 相当）。

**手順1：`requirements.txt` にバージョンを固定して追記**

```
# python/requirements.txt
fastapi==0.115.0
uvicorn==0.30.0
...
numpy==2.0.0    # ← 追加したいライブラリをバージョン固定で追記
```

> **バージョンの確認方法：** https://pypi.org で検索して最新の安定版を確認します。

**手順2：コンテナを再起動（自動でインストールされる）**

```bash
docker-compose restart python
```

コンテナ起動時に `pip install -r requirements.txt` が自動実行されるため、追記したライブラリが自動でインストールされます。

**手順3：Git にコミット**

```bash
git add python/requirements.txt
git commit -m "feat: numpy を追加"
```

> **注意：** バージョンを固定せず `numpy` のように書くとメンバーごとに異なるバージョンが入る可能性があります。必ず `numpy==2.0.0` のようにバージョンを固定してください。

## 16. ローカル開発スタブ（Python 実エンジンなしで AI 機能を確認する）　🐳 Dev Container

マッチング判定・人材プロフィール要約は Python（FastAPI）側の AI エンジンに依存します。実エンジンは
AWS Bedrock / Google Maps 等に依存し手元で動かせないため、**Laravel 側の画面フローを手動確認したい場合は、
最小の FastAPI スタブをローカルで起動して差し替えます**。

> **これらのスタブは Git 管理対象外です（コミットしない）。** 各自のローカルで `python/` 配下に作成して使います。
> Laravel 側は接続先を環境変数で切り替えるだけで、アプリのコードは一切変更しません。実エンジンに戻すときは
> 環境変数を元に戻します。

### ポートの割り当て

| ポート | 用途 |
|---|---|
| 8001 | Python 本体アプリ（`docs` の標準構成） |
| 8002 | マッチングスタブ（`dev_matching_stub.py`） |
| 8003 | 人材要約スタブ（`dev_ai_summary_stub.py`） |

> 同一ポートで複数起動すると `address already in use (errno 98)` になります。本体アプリ（8001）とは別ポートで
> 起動してください。

### 16-1. マッチングスタブ（`POST /api/v1/matching/calculate`）

`python/dev_matching_stub.py` を作成します（**コミットしない**）。

```python
# python/dev_matching_stub.py（コミットしない）
import time

from fastapi import FastAPI
from fastapi.responses import JSONResponse

app = FastAPI()


@app.post("/api/v1/matching/calculate")
def calculate(body: dict):
    # NProgress バー（遷移中ローディング）の確認用に AI 計算の待ちを疑似再現する。
    time.sleep(3)
    eid = body.get("engineer_id")

    # engineer_id で空状態・エラーを疑似再現し、結果画面の出し分けを確認する。
    # error_code はトップレベルで読むため JSONResponse で素の body を返す（HTTPException だと detail にネストされる）。
    if eid == 21:  # 候補案件なし（422）→ emptyReason=no_match
        return JSONResponse(status_code=422, content={"error_code": "NO_ACTIVE_PROJECT"})
    if eid == 22:  # 正常応答だが matches 空（200）→ emptyReason=no_match
        return {"engineer_id": eid, "generated_at": "2026-07-15T00:00:00+09:00", "matches": []}
    if eid == 23:  # エンジン通信失敗（504）→ emptyReason=engine_error（＋トースト）
        return JSONResponse(status_code=504, content={"error_code": "UPSTREAM_TIMEOUT"})
    if eid == 25:  # 人材が存在しない／非掲出（404）→ 404 ページ
        return JSONResponse(status_code=404, content={"error_code": "ENGINEER_NOT_FOUND"})

    return {
        "engineer_id": eid,
        "generated_at": "2026-07-15T00:00:00+09:00",
        "matches": [
            {"project_id": 1, "match_score": 92, "match_rank": "A",
             "ai_score_reason": "必須スキルに高く一致。", "ai_comment": "即戦力として推薦。", "ai_missing": None},
            {"project_id": 2, "match_score": 74, "match_rank": "B",
             "ai_score_reason": "一部工程の経験が不足。", "ai_comment": "検討可能。", "ai_missing": "詳細設計の経験"},
            {"project_id": 3, "match_score": 47, "match_rank": "D",
             "ai_score_reason": "単価・勤務地条件が乖離。", "ai_comment": "見送り推奨。", "ai_missing": "リモート可否"},
        ],
    }
```

```bash
# 起動（python コンテナ内）
uvicorn dev_matching_stub:app --host 0.0.0.0 --port 8002
```

```dotenv
# laravel/.env（ローカルのみ）。コンテナ間通信なのでホスト公開は不要。
MATCHING_ENGINE_URL=http://python:8002
```

> 返す `project_id` は事前に DB（PipelineSeeder / ProjectFactory 相当）に存在させておくこと（Laravel が案件情報を
> DB 突合するため）。

### 16-2. 人材要約スタブ（`POST /api/v1/ai/profile-summary`）

`python/dev_ai_summary_stub.py` を作成します（**コミットしない**）。人材登録・編集で `appeal_note` を入力すると
呼ばれます。`engineer_id` の**下1桁**で挙動を出し分けます。

```python
# python/dev_ai_summary_stub.py（コミットしない）
import time

from fastapi import FastAPI
from fastapi.responses import JSONResponse

app = FastAPI()


@app.post("/api/v1/ai/profile-summary")
def profile_summary(body: dict):
    # AI ローディングオーバーレイ（保存中の全画面表示）の確認用に生成の待ちを疑似再現する。
    time.sleep(3)
    eid = body.get("engineer_id")

    # engineer_id 下1桁で挙動を切り替える：
    #   末尾 3 → 上流障害（504）：登録/更新は成功しつつ「AI要約の生成に失敗しました。」トースト（ai_summary は NULL）
    #   末尾 2 → 空出力（200・空）：失敗ではないため NULL 据え置き・トーストなし
    #   それ以外 → 正常（200）：要約テキストを返し Laravel が保存する
    if eid is not None and eid % 10 == 3:
        return JSONResponse(status_code=504, content={"detail": "gateway timeout"})
    if eid is not None and eid % 10 == 2:
        return {"engineer_id": eid, "ai_summary": "",
                "ai_summary_generated_at": "2026-08-07T10:00:00+09:00"}

    return {
        "engineer_id": eid,
        "ai_summary": (
            "PHP / Laravel を中心に約8年の開発経験を持ち、要件定義から実装・テストまで一貫して担当できる。"
            "チームリードとして若手育成にも携わり、顧客折衝経験もあるため上流工程からの参画に適性がある。"
        ),
        "ai_summary_generated_at": "2026-08-07T10:00:00+09:00",
    }
```

```bash
# 起動（python コンテナ内）
uvicorn dev_ai_summary_stub:app --host 0.0.0.0 --port 8003
```

```dotenv
# laravel/.env（ローカルのみ）。未設定なら MATCHING_ENGINE_URL → http://python:8001 にフォールバックする。
AI_SUMMARY_URL=http://python:8003
```
