## 1. プロジェクト概要

| 項目 | 内容 |
|---|---|
| プロジェクト名 | 国内SES向け 人材・案件マッチングシステム開発 |
| 目的 | SES営業・コーディネーターの業務効率を劇的に向上させるマッチング支援ツールの開発 |
| 開発期間 | 4ヶ月（90人日） |
| 開発開始日 | 2026/04/01 |
| リリース目標日 | 2026/06/30 |

### 1.1 背景・目的

本システムは求職者向けの汎用求人サイトではなく、SES営業・コーディネーターが社内業務で使用する**B2B向け営業支援ツール**である。

現状の課題として、汎用求人サイトは以下の点でSES業務に不向きである。
- 求職者本人が操作することを前提とした設計になっている
- 外国籍判定・在留資格管理など不要な機能が多い
- SES特有の商習慣（商流・単価レンジ・工程経験）に対応していない

本システムはこれらの課題を解決し、4ヶ月で実務レベルの価値を創出することを目標とする。

## 2. システムコンセプト

### 2.1 基本方針

- **対象ユーザー**：SES営業担当・コーディネーター（社内利用）
- **前提**：日本人SES・国内商流に特化
- **方針**：余分な機能を削ぎ落とした特化型システム

### 2.2 4つの柱

| 柱 | 概要 |
|---|---|
| 1. 人材管理 | 経歴・希望条件のDB管理 |
| 2. 案件管理 | 国内SES要件準拠のDB管理 |
| 3. マッチング＆AI | ルールベーススコアリング＋AI推薦理由生成 |
| 4. 進捗管理 | 提案〜参画までのパイプライン管理 |

## 5. 機能要件

### 5.1 人材管理

#### 5.1.1 概要
SES営業が実際に使える人材プロファイルを管理する機能。  
スキルだけでなく、工程経験・顧客折衝力・勤務形態まで管理する。

#### 5.1.2 管理項目

| 項目 | 内容 |
|---|---|
| 基本情報 | 氏名・年齢・最寄駅 |
| ステータス | 提案可・面談中 等 (※QA回答待ち)|
| 提案可能タイミング | 稼働開始可能時期 |
| スキル | 技術スキル（フリーテキスト・タグ） |
| 工程経験 | 要件定義／基本設計／詳細設計／開発／テスト／保守運用 |
| 顧客対応力 | 顧客折衝経験の有無・自己PR |
| 勤務形態 | 常駐可／一部リモート可／フルリモート希望 |
| タグ | 検索用タグ（マスタ管理） |

> **未確定(No.2)**：ステータス確認中

#### 5.1.3 操作
- 一覧表示・検索・フィルタ
- 新規登録・編集・削除
- CSV入出力

---

### 5.2 案件管理

#### 5.2.1 概要
国内SESの商習慣に最適化された案件掲載チケット形式で管理する。

#### 5.2.2 管理項目

| 項目 | 内容 |
|---|---|
| 必須スキル | Java/Spring Boot・AWS等（例） |
| 尚可スキル | React/Vue.js・CI/CD等（例） |

| 商流 | 商流の種別 |

> **未確定(No.14)**：単価確認中

#### 5.2.3 操作

- 新規登録・編集・削除
- CSV入出力

### 5.3 マッチング機能

#### 5.3.1 スコアリングロジック

100点満点のルールベーススコアリングにより、人材と案件の適合度を算出する。

| 評価項目 | 配点 |
|---|---|
| 必須スキル一致 | 30点 |
| 工程経験一致 | 20点 |
| 尚可スキル一致 | 10点 |
| 単価一致 | 10点 |
| 勤務地／通勤条件一致 | 10点 |
| 勤務形態一致 | 10点 |
| 稼働開始時期一致 | 5点 |
| 顧客折衝／人物要件一致 | 5点 |
| **合計** | **100点** |

#### 5.3.2 ランク定義

| ランク | スコア | 意味 |
|---|---|---|
| A | 80点以上 | 即提案レベル |
| B | 65〜79点 | 検討可能 |
| C | 50〜64点 | 条件交渉次第 |
| D | 49点以下 | 見送り推奨 |

> **未確定(No.31)**：スコアリングの配点確認中

#### 5.3.3 マッチング実行トリガー

手動実行はマスト。  
また、可能であれば案件登録時に自動実行

#### 5.3.4 AI補助機能

評価はルールベースで行い、AIは提案の手間を削減するアシスタントとして機能する。

| 機能 | 内容 |
|---|---|
| 推薦理由の自動生成 | なぜこの人材が案件に合うのかを言語化 |
| 不足条件の説明 | 満たしていない要件のピックアップ |
| 職務経歴の要約 | 長い経歴書から強みとスキルタグを抽出 |

> **未確定（M-03）**：AI出力の文字数・フォーマット要件は質問表回答後に確定する。

### 5.4 進捗管理

#### 5.4.1 パイプライン

提案から参画までを以下のステータスで一元管理する。

```
未検討 → 候補 → 提案予定 → 提案済 → 書類選考中 → 面談調整中 → 面談済 → 参画決定
                                                                    ↓
                                                              見送り／保留
```

#### 5.4.2 管理項目

| 項目 | 内容 |
|---|---|
| 担当営業 | 担当者名 |
| 最終更新日 | 自動記録 |
| 顧客コメント | フリーテキスト |
| NG理由 | 見送り・保留時の理由 |
| 次回アクション予定日 | フォローアップ日 |

> **未確定（P-01）**：ステータスの最終定義は質問表回答後に確定する。
> **未確定（P-02）**：ステータス変更の権限設計は質問表回答後に確定する。
> **未確定（P-03）**：次回アクション予定日のアラート機能の要否は質問表回答後に確定する。
> **未確定（P-04）**：カンバン以外の一覧表示ビューの要否は質問表回答後に確定する。

## 6. 非機能要件

> ※以下はQA回答（技術・インフラカテゴリ）をもとに確定する。現時点は暫定記載。

| 項目 | 内容 | ステータス |
|---|---|---|
| 性能 | 同時利用ユーザー数 | ※要確認 |
| 可用性 | 稼働時間・メンテナンス方針 | ※要確認 |
| 保守性 | リリース後サポートスコープ | ※QA回答待ち（Q-04） |

> **セキュリティ**：・HTTPS通信・パスワードハッシュ化・アクセス制御・操作ログ保存・個人情報の適切な制御・CSRF/XSS/SQLインジェクション対策
> **レスポンスタイム**：一覧検索：3秒以内、詳細表示：2秒以内、通常API：1秒前後
> **対応ブラウザ**：Windowsのクロームをマスト。その他のブラウザやOSは工数があまりかからなければケアする。ただし、工数がかかりすぎる場合は不要。
