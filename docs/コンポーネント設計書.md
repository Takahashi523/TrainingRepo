### 1-3. shadcn/ui との責務分担

| 責務 | 方針 |
|---|---|
| フォームパーツ（Input / Select / Checkbox / Label） | shadcn に完全委任。ラップしない |
| ボタン | shadcn `Button` の `variant` / `size` で対応。ラップ不要 |
| モーダル・確認ダイアログ | shadcn `Dialog` をベースに `ConfirmDialog` でラップ（props簡略化のため） |
| ポップオーバー（吹き出し・凡例） | shadcn `Popover` をそのまま使用。外側クリック・Esc での閉じる操作、フォーカス管理、配置調整は自前実装せず Radix に委任する |
| ドロワー（右パネル） | shadcn `Sheet` をベースにドメイン固有コンポーネントでラップ |
| バッジ | shadcn `Badge` をベースに `StatusBadge` / `RankBadge` でラップ（色ロジックをカプセル化） |
| テーブル | shadcn `Table` をそのまま使用 |
| トースト通知 | shadcn `Toaster` + `useToast` をそのまま使用 |
| スキルタグ表示 | shadcn に該当なし → `SkillTag` として独自実装（必須/尚可のボーダースタイル切り替え） |
| カードUI（人材・案件・マッチング・パイプライン） | shadcn `Card` をベースにドメイン固有コンポーネントでラップ |
| ページネーション | shadcn に該当なし → `Pagination` として独自実装 |

> **【2026-08-14 修正】`SkillTagDetail` の詳細表示を自前実装から shadcn `Popover` に切り替えた。**
> **背景：** 表示部分を `useState` ＋ `document` への `mousedown` リスナ（外側クリック検知）＋
> `absolute` 配置の `div` で自前実装しており、Esc で閉じられない・フォーカスが移動しない・
> 親要素の `overflow` で見切れうる、といった差分が既存の `Popover` 利用箇所との間にあった。
> **理由：** 同じ「押下で開く吹き出し」を画面ごとに別方式で持たないため。導入済みの Radix に
> 委任することで、キーボード操作・フォーカス管理・配置調整を個別実装せずに揃えられる。
> 併せて開閉記号を文字グリフ（▲ / ▼）から lucide の `ChevronUp` / `ChevronDown` に統一した。

### 1-4. Inertia.js 設計上の注意点

- **ページコンポーネントはサーバーからのデータを `usePage().props` で受け取る。** Axios / fetch による別途APIコールは原則使わない
- **フォーム操作は `useForm()`** を使い、バリデーションエラーも `errors` オブジェクトで受け取る
- **ページ遷移は `router.get()` / `router.visit()`**、データ送信は `form.post()` / `form.put()` / `form.delete()`
- **マッチング実行も通常の Inertia 遷移（`router.get('/engineers/{id}/matching')`）で行う。** Python AI 連携は Laravel コントローラがサーバー側で同期呼び出しし、結果を props として返すため、フロントからの Axios 非同期リクエストは行わない。AI 計算中の待機表示は、この遷移の `onStart`/`onFinish` に紐づけて遷移**元**で `AiLoadingOverlay` を出す
- SSR は本スコープ外のため考慮不要

### WF_01 ログイン画面

**ページコンポーネント：** `Pages/Auth/Login.tsx`（Laravel Breeze が生成）

**使用レイアウト：** `GuestLayout`（Breeze 生成）

**設計方針：**  
Laravel Breeze の Inertia + React テンプレートが生成するファイルをそのまま使用する。カスタムコンポーネントの新規作成は不要。システム名「Nexus」のロゴテキスト表示はレイアウト内で対応する。

**ページ内コンポーネント構成（Breeze標準）：**

```
Pages/Auth/Login.tsx（Breeze生成）
  ├── GuestLayout
  ├── Input（shadcn）  ← メールアドレス
  ├── Input（shadcn）  ← パスワード（type="password"）
  ├── Label（shadcn）
  └── Button（shadcn）  ← ログインボタン
```

**タブUIの設計変更メモ（2026-07-08）：**

当初設計では進行中／完了済みの切り替えを shadcn `Tabs`（`TabsList` / `TabsTrigger` / `TabsContent`）で1ページ内に実装する想定だった。実装時に以下の理由で **別ルート・別ページ ＋ 独自 `PipelineTabHeader`** に変更している。

- **結論**：`PipelineTabHeader` を独自コンポーネント（`Pagination` / `SkillTag` などと同じ「shadcn に該当機能がない／方針が合わない独自実装」枠）として位置づける。フォームパーツ（Input / Select / Textarea / Button）は §1-3 のとおり shadcn へ完全委任する方針を維持し、進捗管理配下のネイティブ `<input>` / `<textarea>` / `<select>` / `<button>` は shadcn 版へ置換済み（2026-07-08）。タブ見出しの `<button>` のみ、下線タブという独自UIの一部として例外的にネイティブを許容する。
